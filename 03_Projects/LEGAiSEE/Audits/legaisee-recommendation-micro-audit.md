## 4 divergent "recommendation" implementations — genuinely different domains, not simple duplicates
1. **modules/recommendation_module.php — THE live one.** Wired via kernel/module_registry.php → shell.php sidebar. Reads data/cases/*.json 'patterns' field, maps known patterns (ops_delay, pricing_pressure, lead_friction, labor_issue) to canned action text, returns proper UIC-contract shape (type=list, items). Real, reachable, working.
2. **engine/recommendation_engine.php** — separate live path: required by api/v8/recommendations.php (a real, reachable API endpoint). Per-case, reads insights.json (type field: risk_vs_growth/clean_opportunity), writes recommendations.json. Reachable via API, NOT via the module-shell UI — a second, independent live path with different logic than #1.
3. **kernel/recommendation_engine.php** — different domain entirely: marketing-content recommendations (posting frequency, landing-page CTAs) generated by keyword-matching raw insight TEXT (marketing/social/website), requires kernel/insight_generator.php. Wired to: (a) old api/recommendations_generate.php, which reads from the dead fake data/network/ flat-JSON universe already confirmed dead in [[legaisee-brain-micro-audit]] — so that path is fake; (b) kernel/task_generator.php's createTasksFromRecommendations() — but that function is never called anywhere AND has a real bug (references undefined $pdo instead of the $conn parameter it was given) — dead AND broken.
4. **engine/system_recommendation_engine.php** — system-wide governance POLICY generator, different scope again (reads system_insights.json, writes system_recommendations.json, generates rules like "Prioritize Engagement Stability Over Volume" that are meant to bind other engines). Written as a fire-once top-level script, not a reusable function — different design pattern than the other 3. Only reference anywhere is brain_module.php's health check, which checks the WRONG PATH (see systemic bug below) — so effectively orphaned.

## 3 API endpoints, 3 different backing patterns (not 3 versions of the same thing)
- api/v8/recommendations.php → engine/recommendation_engine.php (real per-case JSON read) — REAL, reachable
- api/recommendations_generate.php (old, non-v8) → kernel/recommendation_engine.php, reads the dead fake data/network/net_case_X.json universe — FAKE paradigm
- api/v8/recommendations_generate.php → raw mysqli SELECT against processing_queue WHERE task_type='recommendation', doesn't call ANY of the 4 engine files — REAL DB paradigm (matches [[legaisee-brain-micro-audit]]'s Group A), but nothing anywhere actually INSERTs task_type='recommendation' rows (the one function that would, createTasksFromRecommendations, is dead/broken per above) — so in practice this endpoint always returns empty.

## SYSTEMIC BUG found while tracing connectivity (bigger than this cluster)
brain_module.php's entire engine-health-check block points at a **`/system/` directory that does not exist anywhere in the codebase**:
```
'cross_case_engine'     => file_exists(__DIR__ . '/../system/cross_case_engine.php'),
'insight_engine'        => file_exists(__DIR__ . '/../system/system_insight_engine.php'),
'decision_engine'       => file_exists(__DIR__ . '/../system/decision_engine_v2.php'),
'recommendation_engine' => file_exists(__DIR__ . '/../system/system_recommendation_engine.php'),
'policy_engine'         => file_exists(__DIR__ . '/../system/policy_enforcement_engine.php'),
```
All 5 real files exist, just not at that path — they're at engine/cross_case_engine.php, engine/system_insight_engine.php, engine/decision_engine_v2.php, engine/system_recommendation_engine.php, engine/policy_enforcement_engine.php (cross_case_engine.php also separately exists at modules/cross_case_engine.php — another naming collision). Result: **all 5 engine-health flags in the Brain module are permanently false**, regardless of whether the real engines work. Worth cross-referencing against [[legaisee-brain-micro-audit]] and [[legaisee-ui-micro-audit]]'s open Brain Dashboard thread — this likely explains any "engines showing unhealthy/red" symptom John may have seen on a Brain-related screen.

## Other bugs found (documentation only, no fix made)

Separately, cli/worker.php calls `buildPredictiveInsights()` twice in a row (lines ~9 and ~14), with a redundant duplicate require of predictive_intelligence_engine.php in between — apparent copy-paste duplication, not two different data sets.
