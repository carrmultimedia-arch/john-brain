- [stated] Shared a published Google Doc ("Johnjobs rev 9-9-26") laying out a "Company-First Reverse Job Search" methodology — instead of job posting → application → ATS → wait, the model is candidate capabilities → find companies → detect signals/changes → identify latent or emerging need → find the human decision-maker → direct evidence-based contact → conversation → job
- [stated] The doc itself (GPT-authored) proposes evolving [[jobhunt-command-center]] (johnjobsv2.legaisee.com) rather than building a new system: keep existing Jobs/Applications/Resume/Search/Tracker intact, and add a parallel Company-first workspace (Companies, Signals, Opportunities, People, Contact Paths, Watchlist, Daily Mission queue) that connects to the existing objects
- [stated] Core proposed shift: make COMPANY (not Job) the persistent central database object, since jobs/people/signals come and go but the company record accumulates history
- [stated] Doc proposes a phased build: V1 manual/human-operated company database + research worksheet + daily action queue + outcome funnel; V1.5 adds assisted research (auto-discovery of company sites/careers/LinkedIn, AI summarization/suggested classification); V2 adds automated watcher (cron checks public sources, detects changes, generates signals); V3 is a persistent job-hunting intelligence agent
- [stated] Doc's proposed next step (not yet started): inspect the actual current johnjobsv2 production files/database structure before writing any code, then design the smallest V1 modification around what already exists, rather than coding from the archival doc alone
